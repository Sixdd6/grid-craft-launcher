# Plan 12: browser rows — latest version and install state

Date: 2026-09-08. Branch: `plan-12-latest`. Status: in progress.
Spec: `docs/superpowers/specs/2026-09-08-browser-latest-design.md` (approved).

## Summary

Each browser search row shows the newest version for the target instance's Minecraft version
and loader, whether it is installed, and whether the installed copy is older, with an
Add/Update/Installed button. Core gains a bounded-concurrency `latest_versions` resolver with an
in-memory version cache and an `install_state` comparator; CurseForge gains `latestFilesIndexes`
parsing so a hit can answer "latest" without an extra call. The browser screen runs this as a
per-page job after search results paint, guarded by a generation counter like `fetch_icons`.

## Global constraints

No `unwrap`/`expect` outside tests; thiserror in core; no network in tests; element ids
`<thing>_<kind>`; sample data only in `Preview*`; every new row field starts empty/unknown;
`just check` per task; commits end with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

## Design seams settled here

- `Launcher::latest_versions` takes `&[SearchHit]` (source-, kind- and index-tagged), not bare
  ids, so a CurseForge hit's `latestFilesIndexes` reaches the resolver. Documented on the method.
- `SearchHit.latest_files: Vec<LatestFileIndex { game_version, loader: Option<u32>, file_id }>`;
  always empty for Modrinth (no such field; Modrinth always calls `versions`).
- One in-memory cache serves both calls: `Launcher.version_cache:
  Mutex<HashMap<(SourceId, project_id, Option<minecraft>, loaders_joined), Arc<Vec<Version>>>>`,
  filled by `cached_versions(source, project_id, filter)`. No disk file, no eviction (spec:
  lifetime of the launcher). The CurseForge index fast path writes a one-element list through the
  same cache; an installed id absent from it falls to the spec's "absent → older" rule.
- New pure `content::pick_latest(versions, kind, minecraft: Option<&str>, loader) ->
  Option<Version>`: Minecraft filter only when `Some`; `compatible_loaders` for mods only when
  the loader is not `None`; sort (kind desc, published desc); first wins.
- `content::entry_holding_file` becomes `pub(crate)` for reuse from `launcher`.
- `published` comparison parses both sides with `time::OffsetDateTime` (RFC 3339); on a parse
  failure fall back to a string compare and `warn`, never fail the row.
- A target change re-runs the whole per-row job (latest depends on the target too); the cache
  keeps it cheap. Noted on the handler.
- `Shared.latest_generation` is its own counter, bumped in `search()` beside `icon_generation`.
- Update pins `latest_id` through `content::add` at depth 0; `add_request` gains
  `version: Option<String>`; after success only that row's state is refreshed.
- `install_state` takes the `VersionTarget` as well (accepted deviation from the spec's
  four-argument form) so the installed version's date is looked up in the same list.

## Tasks

### Task 1 — core: CurseForge `latestFilesIndexes` (coder)

`LatestFileIndex` in `types.rs`, exported with `SearchHit`; `SearchHit.latest_files` (every
existing `SearchHit {` literal gains `vec![]`). `RawLatestFileIndex { game_version,
#[serde(default)] mod_loader: Option<u8>, file_id: u32 }` (camelCase), `RawMod.latest_files_indexes`
with `#[serde(default)]`, mapped in both hit builders (`loader: mod_loader.map(u32::from)`,
`file_id.to_string()`). Tests: a `RawMod` with Fabric and Forge index entries maps; the search
fixture extended by hand with a `latestFilesIndexes` array; existing tests keep passing.
Commit: `feat(core): parse CurseForge latestFilesIndexes onto SearchHit`.

### Task 2 — core: `pick_latest`, visibility (coder)

As in the seams. Tests: no Minecraft filter; Minecraft filter excludes; `Loader::None` skips the
loader filter even for mods; release beats an earlier beta; date breaks a tie. Commit:
`feat(core): pick_latest and entry_holding_file visibility`.

### Task 3 — core: resolver, state, cache (coder)

Types `#[derive(Debug, Clone, PartialEq)]`. `latest_versions(source_id, hits, target) ->
Vec<LatestVersion>` inside `self.block_on`, a `Semaphore::new(4)` over per-hit futures (mirror
`download::download_all`); CurseForge index match → `files_batch(&[file_id])` → one-element cache
entry; otherwise `cached_versions` with the filter `content::add` would build → `pick_latest`;
a per-hit error becomes `version: None`. `install_state(slug, source, project_id, target, latest)`:
entry via `instances::content::installed` else `entry_holding_file`; none → `NotInstalled`;
same id → `Installed`; else look the installed id up in the cached list: present → compare
`published` (Older when latest is newer), absent → Older when ids differ. Tests: FakeSource for
filters and the no-target case; CurseForge over wiremock proving the fast path skips `files` and
the fallback; cache proven with a call counter; the four `install_state` outcomes plus the parse
fallback. Confirm `time`'s `parsing` feature. Commit: `feat(core): latest_versions resolver and
install_state comparator`.

### Task 4 — UI (slint-designer)

`SearchRow` fields start `""`/`"unknown"`. Pure converter `(LatestVersion, InstallState) → four
fields` with unit tests. `fetch_latest` after each search done closure (not for modpack rows):
one `Bridge::run` job → `latest_versions` then `install_state` per resolved hit → guard on
`latest_generation` → patch rows in place with `set_row_data`. Update: `add_request(version:
Some(latest_id))`, then refresh that row. Target change re-runs the job. `browser.slint`: state
line ("Latest for <mc> <loader>: <n>", "Latest: <n>", "No version for <mc> <loader>",
"Checking…"; "Installed: <n>"; `↑` before Latest when older); `row_install` reads Add / Update /
a muted disabled "Installed". `just check`, `slint-viewer --check`. Commit: `feat(ui): latest
version and install state on browser rows`.

### Task 5 — flow test and fixes

`support/mod.rs`: three hits with distinct projects (installed older, installed current, not
installed) with matching version fixtures and served jars. `flow_content.rs` sub-flow: search →
wait on the row texts → assert the three labels and states → click Update on the older row →
old jar gone, new present, row reads Installed. Fix what it finds. Commit: `test(ui): browser
latest-version and install-state flow; fixes found along the way`.
