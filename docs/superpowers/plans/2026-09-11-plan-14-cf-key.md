# Plan 14: CurseForge key from the build, not from the user

Date: 2026-09-11. Branch: `plan-14-cf-key`. Status: in progress.
Research: `docs/research/2026-09-11-curseforge-access.md`.

## Summary

The CurseForge terms license a key to the applicant and forbid sharing it. The application
addresses a project, not an end user, so the launcher stops asking users for a key. The key
ships inside release builds, read at compile time from a CI secret, the way Prism does it.
The `CURSEFORGE_API_KEY` environment variable stays as the development path (api-verifier,
fixture recording). `config.toml` no longer holds a key and the Settings screen has no field.

## Decisions

- Precedence in `Config::curseforge_api_key()`: `CURSEFORGE_API_KEY` env (non-blank) first,
  then `option_env!("GCL_CURSEFORGE_API_KEY")` compiled into `gcl-core`. `self` is no longer
  read; keep the method on `Config` so callers do not change.
- `Keys.curseforge_api_key` is removed from the struct. A `config.toml` that still has it
  loads fine (serde ignores unknown keys), and `Config::load` logs one `warn!` naming the key
  as no longer read, without its value.
- Tests that turned CurseForge on through `config.keys.curseforge_api_key` use a new seam
  `Launcher::with_curseforge_key(key: impl Into<String>) -> Self`, next to `with_icon_hosts`.
  It overrides the resolver for that launcher only, so no test touches the environment.
- `gcl config show` prints `curseforge = "enabled" | "disabled"` in place of the key state.
- Settings screen: the key row goes away. In its place one muted line:
  "CurseForge: enabled" or "CurseForge: off (this build carries no key)". Ids
  `curseforge_key_field` and `curseforge_key_button` are removed from the ids doc.
- Release workflow: `dist-workspace.toml` gains `github-build-setup =
  ".github/workflows/dist-build-setup.yml"` whose one step writes
  `GCL_CURSEFORGE_API_KEY` from `secrets.GCL_CURSEFORGE_API_KEY` to `$GITHUB_ENV`. The
  workflow is regenerated with `dist generate`. `ci.yml` needs no key.
- Never print or log `GCL_CURSEFORGE_API_KEY` either (AGENTS.md).
