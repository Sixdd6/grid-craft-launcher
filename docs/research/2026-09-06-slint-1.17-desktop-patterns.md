# Slint 1.17 desktop patterns

Researched 2026-09-06 for the `slint-ui` skill and MVP plan 5. Items marked UNCERTAIN were not
confirmed against the 1.17 docs; check `cargo doc -p slint --open` before relying on them.

## Rust API

- `slint::include_modules!()` pulls in the components `slint-build` compiled.
- Each exported component: `Name::new() -> Result<Name, PlatformError>`, `run()`, `show()`,
  `hide()`, `as_weak()`, `clone_strong()`, `window()`. Properties: `get_x()`/`set_x()`.
  Callbacks: `on_x(|args| ...)`, `invoke_x(args)`.
- `slint::Weak<T>`: `upgrade()` (event-loop thread only) and
  `upgrade_in_event_loop(|comp| ...)` (any thread; queues onto the loop). Weak is `Send`.
- `slint::invoke_from_event_loop(|| ...)`: run a `Send + 'static` closure on the UI thread.
- `slint::spawn_local(future)`: runs a future on the UI thread; tokio futures need
  `async_compat::Compat` or must be driven elsewhere. This project runs core work on its own
  threads and posts results back with `upgrade_in_event_loop`; it does not use `spawn_local`.
- `slint::Timer` (`start(TimerMode::Repeated, Duration, f)`, `single_shot`, `stop`) fires on the
  UI thread only and stops when dropped.
- `slint::quit_event_loop()` is thread-safe.
- `SharedString` (copy-on-write; `From<&str>`), `ModelRc<T>` (not `Send`; UI thread only),
  `VecModel<T>` (`push`, `remove`, `set_row_data`, `set_vec`, `row_count`), `FilterModel`,
  `MapModel`, custom `Model` impls via `ModelNotify`.
- `slint::Image::load_from_path`, `Image::from_rgba8(SharedPixelBuffer)`; `Image` is not `Send`.
  Decode on a worker into a `SharedPixelBuffer`, build the `Image` on the UI thread.
- `Window::set_fullscreen`, `set_maximized`, `scale_factor()`, `on_close_requested`,
  `take_snapshot()` (RGBA buffer; useful for screenshots).

## Slint language

- `export struct Name { field: type, ... }` maps to a Rust struct with the same fields
  (`string` → `SharedString`, `int` → `i32`, `float` → `f32`, `bool`, `image` → `Image`,
  `[T]` → `ModelRc<T>`).
- `export global Name { in-out property <T> x; callback y(int) -> string; }` is reachable
  from Rust with `component.global::<Name>()`, then `get_x`/`set_x`/`on_y`/`invoke_y`.
- Property directions: `in` (set from outside), `out` (read from outside), `in-out`, private.
- `std-widgets.slint`: `ListView` (virtualized), `ScrollView`, `LineEdit`, `TextEdit`,
  `Button`, `ComboBox`, `CheckBox`, `Switch`, `Slider`, `SpinBox`, `ProgressIndicator`
  (`progress` 0..1 or `indeterminate`), `TabWidget`, `StandardListView`, `StandardTableView`.
- Style: `slint_build::CompilerConfiguration::new().with_style("fluent")` at build time or
  `SLINT_STYLE` env at run time; styles `fluent`, `material`, `cupertino`, `cosmic`, `qt`,
  `native`. `Palette` global exposes `color-scheme`, `background`, `foreground`.
- `@image-url("path")` embeds at compile time. `@tr("Text {}", arg)` formats and marks for
  translation; use it or Rust-side formatting, since Slint has no `format!`.
- `TouchArea` (`clicked`, `has-hover`, `pressed`, `pointer-event`), `FocusScope`
  (`key-pressed(event) -> EventResult`, `Key.UpArrow` etc.), `PopupWindow`
  (`close-on-click-outside`, `show()`, `close()`).
- `states [ name when cond: { prop: value; } ]`, `animate prop { duration: 150ms; }`,
  `color.with-alpha(0.5)`, `brighter`, `darker`.

## Threading pattern used by this project

```rust
let launcher = Arc<Launcher>;         // Launcher is Send + Sync
let weak = app.as_weak();
std::thread::spawn(move || {
    let result = launcher.some_blocking_call();
    let _ = weak.upgrade_in_event_loop(move |app| { /* set properties, update models */ });
});
```

Core events (`EventSink` receiver) are drained by one forwarder thread that batches events
every ~50 ms and posts one closure per batch to the UI thread.

## Build

`slint-build::compile_with_config(path, CompilerConfiguration::new().with_style(..).with_include_paths(..).embed_resources(EmbedResourcesKind::EmbedFiles))`.
Preview: `slint-viewer --auto-reload ui/app.slint` or the VS Code Slint extension.

## Gotchas

- `ListView` virtualizes; fine for thousands of rows.
- Never capture the strong component handle in its own callbacks (reference cycle); capture `as_weak()`.
- `ModelRc`/`Image` are UI-thread only; build them inside the `upgrade_in_event_loop` closure.
- No string or number formatting in Slint; format in Rust and pass `SharedString`.
- Software renderer: clipped rounded corners have artifacts; the project uses FemtoVG (GPU).
- CONFIRMED (compiles and runs in `gcl-ui`): `min-width`, `min-height`, `preferred-width`, and
  `preferred-height` are ordinary properties on a component that `inherits Window` — see
  `AppWindow` in `ui/app.slint` (`min-width: 960px; min-height: 600px; preferred-width: 1200px;
  preferred-height: 760px;`). No special scoping rule found or needed; they behave like any other
  geometry property on the root component.
- CONFIRMED: a `for row[i] in list: SomeRow { ... }` inside a `ListView` needs each row to set an
  explicit `height:` (every screen here uses `Theme.row-height + Theme.gap`, or a themed
  equivalent). Without a fixed height the list still compiles, but a row-height-per-item is what
  lets `ListView`'s virtualization skip laying out off-screen rows; every `ListView` in `gcl-ui`
  (`screens/instances.slint`, `screens/accounts.slint`, `screens/browser.slint`,
  `screens/instance.slint`, `components/choice-dialog.slint`) sets one.
- Still UNCERTAIN: `SortModel` was not needed or exercised by this project (filtering is done in
  Rust before building the model), so its docs remain unconfirmed against real use.
